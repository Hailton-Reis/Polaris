# OpenCV oficial integrado — P20261117.1

**Continuação:** a [P20261117.2](LIMPEZA_RECORTE_OCR_P20261117_2.md) altera a vida útil de recortes no SDK Kotlin e documenta essa modificação local. A integração e os números abaixo conservam o checkpoint P20261117.1.

17/11/2026, America/Fortaleza. Desenvolvimento para a próxima versão, sem novo APK ou Release. A beta.11 pública permanece P20261116.1/código 112.

## Mudança

O app consumia o pin direto `com.quickbirdstudios:opencv:4.5.3.0` no módulo `ppocr-sdk`. Na beta.11, OpenCV e o runtime C++ ARM64 tinham PT_LOAD abaixo de 16 KiB. A pesquisa [P20261116.3](LEITURA_BACKUPS_P20261116_3.md) identificou uma candidata oficial; esta revisão a integra ao código e à compilação.

O catálogo passa a declarar **`org.opencv:opencv:4.12.0`**, e `ppocr-sdk` usa efetivamente `libs.opencv.android`. O grafo `betaRuntimeClasspath` confirmou essa coordenada pelo SDK e não contém o OpenCV QuickBird. O AAR resolvido pelo Gradle tem o mesmo SHA-256 do artefato oficial previamente pesquisado: `f71846a313388d9da667a59be1e921669fcf792d1ba264b3898253ca789bc3f0`.

O AAR tem minSdk21 e licença Apache-2.0 declarada no POM. O manifesto mesclado do app conserva API mínima 26, ID `app.mihon.tachiyomiat.dev`, versão beta.11/código 112, sem atributos que habilitem depuração/testOnly/profiling por shell. Esse manifesto é intermediário; não constitui verificação de um APK novo. Antes de distribuir, aumentar versão/código acima de 112 e validar o pacote final.

Não houve alteração do SDK Kotlin vendorizado, modelos, algoritmos de OCR, opções da interface ou regras de seleção de arquivos nativos. Não foi necessário `pickFirst` para esconder conflito de runtimes.

## Bibliotecas realmente mescladas

Foi conferida a saída real de `:app:mergeBetaNativeLibs`, com `-Ppolaris.universalArm=true`:

- As **31 bibliotecas** preservam os caminhos das duas ABIs ARM32/ARM64: 16 ARM64 e 15 ARM32, sem x86 no conjunto universal ARM.
- Os quatro arquivos OpenCV/C++ são idênticos aos do AAR oficial, por SHA-256. O runtime selecionado vem desse mesmo artefato.
- As outras **27 bibliotecas permanecem byte a byte iguais** à saída mesclada anterior, registrada antes da integração.
- Máquina/classe ELF conferidas em todas; as 16 ARM64 têm PT_LOAD de pelo menos 16 KiB e congruência entre offset e endereço virtual para páginas de 16 KiB.
- Os consumidores mesclados que importam símbolos anteriormente fornecidos pelo runtime C++ foram conferidos: OpenCV usa 204 dessas referências fortes em cada ABI; nenhum símbolo está ausente do runtime selecionado. Os demais arquivos não apresentaram importações fortes nessa interseção. Isso não certifica toda a ABI C++, namespaces do linker, disponibilidade de APIs do sistema, relocações ou JNI.

O verificador rejeitou dois controles negativos em diretórios temporários: recolocar o C++ ARM64 antigo e retirar o OpenCV ARM32. Foram usados ELF reais; nenhuma biblioteca de produção foi modificada por esses controles.

O conjunto nativo mesclado soma **195.499.800 bytes**, frente a 192.286.636 anteriormente: **+3.213.164 bytes brutos**. Essa diferença não mede tamanho de APK, instalação ou RAM. A troca corrige o requisito observado de alinhamento ELF; não é uma otimização de tamanho.
